# aiovl
## Руководство разработчика ботов VLook

Python SDK • 0.0.1.dev1 • Редакция от 12 октября 2026 года

Практическая документация по текущим исходникам: создание бота, установка, обработчики, кнопки, сообщения, фотографии, PDF и подтверждение обновлений.

### Что представляет собой aiovl

Это экспериментальный асинхронный Python-клиент облачного API ботов VLook. Код бота работает в вашем Python-процессе на компьютере или сервере. VLook доставляет обновления и ответы, но не исполняет загруженный вами код.

Библиотека не является полной заменой aiogram или Telegram Bot API. Имена обработчиков, формы данных и часть методов отличаются.

# 1. Создание бота и доступ пользователей

### Получите параметры в VLook

1. Откройте «Настройки → Разработчикам», включите режим разработчика и дождитесь сохранения настройки.
2. Откройте встроенного помощника VLook BotFather: `@vlook_botfather_bot`.
3. Отправьте `/newbot`, укажите название и username. Завершите мастер кнопкой «Создать бота». `/cancel` отменяет мастер.
4. Сохраните выданный bot token в защищённой конфигурации своего процесса. Не публикуйте его в коде, скриншотах или журналах.
5. Для нового кода достаточно bot token: `Bot(token)` сам узнаёт публичный ID через `getMe`. Копировать ID из BotFather не требуется. Кнопка копирования остаётся полезной для старого кода с явным `bot_id`.

Название: 1-64 символа после удаления пробелов по краям. Username: 5-32 символа, строчные латинские буквы, цифры и `_`; первая буква латинская, окончание `_bot`. Имя `vlook_botfather_bot` зарезервировано.

| Значение | Назначение |
| --- | --- |
| `@example_bot` | Имя для поиска бота в VLook. |
| `botId` с префиксом `bot_` | Публичная идентичность бота; SDK определяет её по токену. Необязательный аргумент для старого кода. Username не является этим ID. |
| Bot token | Секрет, разрешающий операции именно вашего бота. |
| Session token аккаунта | Используется клиентом VLook. Для запуска бота извлекать его не нужно. |
| `chat` из обновления | Адрес конкретного приватного диалога; используйте его при ответе. |

### Обычные пользователи

Для общения с обычными ботами режим разработчика не нужен. Пользователь находит бота по `@username`, открывает чат и отправляет сообщение или `/start`. Открытие чата само по себе не должно восприниматься вашим кодом как полученная команда.

### Жизненный цикл токена

Токен не одноразовый. Один действующий токен используется для многократного чтения обновлений и отправки ответов. Подтверждённая смена токена прекращает действие старого; отзыв отключает бота.

Повторный показ токена в интерфейсе и его повторное использование SDK - разные функции. Ошибка показа не означает, что уже сохранённый действующий токен израсходован. Не выполняйте ротацию автоматически при каждом запуске.

При потере ответа на создание или смену токена сначала проверьте состояние в BotFather. Не повторяйте создание вслепую. Для старой записи, содержащей только хеш токена, восстановление исходного значения невозможно: требуется явная смена токена.

# 3. Полный пример: команда, кнопка, echo

Сохраните как `bot.py`. Командные обработчики зарегистрированы перед общим текстовым; последний callback-обработчик отвечает на неизвестные кнопки.

```python
import asyncio
import getpass
import os
from aiovl import Bot, Dispatcher, Router


def make_router(bot):
    router = Router()

    @router.on_command("/start")
    async def start(update):
        await bot.send_message(
            update["chat"], "Нажмите кнопку или напишите сообщение.",
            request_id="start:" + update["updateId"],
            reply_markup={"type": "inline", "rows": [[
                {"text": "Привет", "callbackData": "hello"}
            ]]},
        )

    @router.on_callback("hello")
    async def hello(update):
        query = update["callbackQuery"]
        await bot.answer_callback_query(
            query["id"], request_id="answer:" + query["id"],
            text="Готово",
        )
        await bot.send_message(
            update["chat"], "Здравствуйте!",
            request_id="hello:" + update["updateId"],
        )

    @router.on_callback()
    async def unknown_button(update):
        query = update["callbackQuery"]
        await bot.answer_callback_query(
            query["id"], request_id="unknown:" + query["id"],
            text="Эта кнопка больше не поддерживается.",
        )

    @router.on_text()
    async def echo(update):
        await bot.send_message(
            update["chat"], update["text"],
            request_id="echo:" + update["updateId"],
        )

    return router


async def main():
    token = os.environ.get("VLOOK_BOT_TOKEN") or getpass.getpass("Bot token: ")
    bot = Bot(token)
    await Dispatcher(
        bot, router=make_router(bot), timeout=0,
        acknowledge=True, retry_transport=True,
    ).run_polling()


if __name__ == "__main__":
    asyncio.run(main())
```

# 4. Обработчики и клавиатуры

### Router: выполняется первый подходящий обработчик

| Регистрация | Какие обновления получает |
| --- | --- |
| `@router.on_command("/start")` | Текст, первое слово которого точно равно `/start`. Аргументы остаются в `update["text"]`. |
| `@router.on_text()` | Обычный текст; ставьте после команд. |
| `@router.on_callback("hello")` | Нажатия с точным `callbackQuery.data == "hello"`. |
| `@router.on_callback()` | Остальные callback; ставьте после специальных. |
| `@router.on_photo()` | Обновления с фотографией. |
| `@router.on_document()` | Обновления с PDF-документом. |
| `@router.on_attachment()` | Любое поддерживаемое вложение; ставьте после специальных. |

Для вложения сначала ищется подходящий обработчик файлов. Если его нет, непустая подпись может попасть в текстовый обработчик; пустое вложение остаётся без обработчика. Dispatcher всё равно продвинет курсор обычного обновления. Поэтому включайте `include_attachments=True` только вместе с обработчиками всех нужных видов.

### Inline-кнопки под сообщением

```python
inline_keyboard = {
    "type": "inline",
    "rows": [[
        {"text": "Статус", "callbackData": "status"},
        {"text": "Помощь", "callbackData": "help"},
    ]],
}
```

Передайте словарь как `reply_markup` в `send_message`. Нажатие создаёт callback; ответьте через `answer_callback_query`. Успешный ответ необходим до подтверждения обновления. Сам ответ на callback не создаёт новое сообщение в чате.

### Reply-кнопки и удаление клавиатуры

```python
reply_keyboard = {
    "type": "reply",
    "rows": [[{"text": "Помощь"}, {"text": "Статус"}]],
}
remove_keyboard = {"type": "remove"}
```

Reply-кнопка отправляет свой текст как сообщение пользователя. Для обработки используйте текстовый обработчик. `remove` отправляется с непустым текстом через `send_message` и снимает reply-клавиатуру.

Лимиты: до 8 строк, до 8 кнопок в строке, максимум 48 кнопок. Подпись кнопки: 1-64 символа; `callbackData`: 1-64 байта UTF-8. Нормализованный JSON разметки - до 8192 байт. URL-кнопки и произвольные поля Telegram разметкой не поддерживаются.

# 5. Форматы входящих обновлений

Обработчик получает словарь. Идентификаторы обновлений и сообщений - десятичные строки, а не Python-числа. `chat` нужно брать из полученного обновления. Ниже приведены только синтетические значения.

### Текст или команда

```json
{
  "version": 1,
  "updateId": "101",
  "botId": "bot_example_01",
  "chat": {"kind": "private", "id": "chat_example_01"},
  "text": "/start"
}
```

### Нажатие inline-кнопки

```json
{
  "version": 1,
  "updateId": "102",
  "botId": "bot_example_01",
  "chat": {"kind": "private", "id": "chat_example_01"},
  "callbackQuery": {
    "id": "callback_00000000000000000000000000000001",
    "messageId": "41",
    "data": "hello"
  }
}
```

### Документ: метаданные без содержимого

```json
{
  "version": 1,
  "updateId": "103",
  "botId": "bot_example_01",
  "chat": {"kind": "private", "id": "chat_example_01"},
  "text": "Подпись к файлу",
  "attachment": {
    "fileId": "media_00000000000000000000000000000001",
    "kind": "document",
    "fileName": "receipt.pdf",
    "mimeType": "application/pdf",
    "size": 120,
    "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
  }
}
```

У фотографии `kind` равен `photo`, MIME - `image/jpeg` или `image/png`, дополнительно обязательны целочисленные `width` и `height`. Подпись хранится в `text` и может быть пустой. Байты скачиваются отдельно через `get_attachment`; URL файла в обновлении нет.

# 6. Справочник: сообщения и обновления

### Только токен и совместимость старого кода

`Bot(token)` и `Dispatcher(bot, router=router)` не требуют `bot_id`. Первая операция выполняет авторизованный `POST /v1/cloud-bots/getMe` с JSON `{"version":1,"operation":"getMe"}`. Токен передаётся только в `Authorization: Bearer …`. SDK принимает только результат `{"version":1,"botId":"bot_…"}`: неправильная версия, другой формат или дополнительные поля отклоняются.

Одновременные операции одного экземпляра разделяют один запрос discovery. Отмена одного ожидающего не отменяет запрос другого; у запроса и ожидающих ограниченные тайм-ауты. Кэш содержит лишь публичный ID. Каждая отправка/чтение снова проходит серверную bearer-авторизацию, поэтому ротация или отзыв токена блокируют дальнейшую работу. `await bot.get_me()` выполняет новую проверку, а не возвращает решение об авторизации из кэша; изменение уже известной идентичности отклоняется.

`get_me()` возвращает `{"version": 1, "botId": ...}`, без username, имени владельца и профиля Telegram. Его можно вызвать заранее для проверки конфигурации. При ошибке discovery нет обхода через owner API, список ботов или извлечение session token. Нужен сервер с endpoint `getMe`; старый сервер без него отклонит новый token-only запуск.

Старые вызовы работают без discovery: `send_message(bot_id, chat, text, request_id=...)`, `get_updates(bot_id)`, `Dispatcher(bot, bot_id, router)`. Method objects сохраняют старый порядок позиционных аргументов. После успешного discovery явный ID другого бота отклоняется локально. Оставлять `bot_id` в старом проекте можно; для нового кода он необязателен.


Все операции ниже асинхронные. Значения `timeout` у отправки - сетевой тайм-аут в секундах. Разрешены конечные положительные значения до 120 секунд.

### Создание клиента

```text
Bot(token, *, transport=None,
    base_url="https://89.124.86.75")
```

`token` - токен бота; `transport` - необязательный адаптер для интеграции или тестов. Для обычного запуска достаточно токена; основной HTTPS origin задан по умолчанию.

### Отправка текста

```text
await bot.send_message(
    chat, text, *, request_id,
    reply_markup=None, timeout=30,
)
```

Текст: 1-4096 символов; переносы строк и табуляция допустимы. Метод возвращает серверный `result`, обычно словарь с `version`, `messageId`, `botId`, `chat`, `text` и необязательным `replyMarkup`. Это результат принятия операции, не подтверждение чтения человеком.

`request_id` обязателен. Он должен оставаться тем же при повторе одной логической операции. Формат: 1-128 ASCII-символов, первый - буква или цифра; далее также допустимы `.`, `_`, `:`, `-`.

### Получение обновлений

```text
await bot.get_updates(
    *, offset=None, limit=100, timeout=0,
    request_timeout=60, include_attachments=False,
)
```

Возвращает список обновлений. `offset` - исключительная нижняя граница: нужны ID строго больше указанного. `limit`: 1-100. `request_timeout` - сетевой тайм-аут. SDK допускает `timeout` 0-50 для серверного ожидания, но текущий контракт сервера используйте с `timeout=0`: long polling не подтверждён. Вложения включаются явно.

### Ответ на callback и подтверждение обновлений

```text
await bot.answer_callback_query(
    callback_query_id, *, request_id,
    text="", show_alert=False, timeout=30,
)
await bot.acknowledge_updates(through)
```

Callback-ответ: до 200 символов, возвращается `{"answered": True, "callbackQueryId": ...}`. `show_alert=True` запрашивает заметное уведомление клиента. Отвечайте без задержки: сервер ограничивает срок действия callback.

`acknowledge_updates` подтверждает обработанный префикс до `through` включительно и возвращает строку курсора. Это отдельная операция: чтение обновлений само по себе не является их подтверждением.

# 7. Получение фотографий и PDF

Media API проверены между SDK и основным HTTPS API 12.10.2026: загрузка, получение, ответ, изоляция доступа, перезапуск и восстановление зашифрованной копии. Это не подтверждает передачу через каждый клиент VLook. В native53/54 пользовательский bot-media UI ещё не реализован; сначала проверьте поддерживающий клиент для своего сценария.

### Подключение обработчиков

Добавьте функцию ниже в `bot.py`. В `main()` после создания `bot` сначала получите `router = make_router(bot)`, затем вызовите `add_media_handlers(router, bot)`. Передайте этот router в Dispatcher и добавьте `include_attachments=True`.

```python
def add_media_handlers(router, bot):
    @router.on_document()
    async def document(update):
        descriptor = update["attachment"]
        attachment = await bot.get_attachment(
            update["chat"], descriptor["fileId"],
        )
        # bytes в памяти; не сохраняем чужое имя как путь.
        pdf_bytes = attachment["data"]
        if attachment["kind"] != "document":
            raise ValueError("Unexpected attachment kind")
        # Здесь ваша обработка PDF. Получение файла само по себе
        # не подтверждает достоверность его содержимого.
        await bot.send_message(
            update["chat"], "PDF получен.",
            request_id="document-received:" + update["updateId"],
        )

    @router.on_photo()
    async def photo(update):
        await bot.send_message(
            update["chat"], "Фотография получена.",
            request_id="photo-received:" + update["updateId"],
        )
```

В этом примере документ скачивается, фотография обрабатывается по метаданным. Для получения её байтов вызовите тот же `get_attachment` с `fileId` фотографии.

### Результат загрузки

```text
await bot.get_attachment(chat, file_id, *, timeout=60)
```

Возвращается словарь дескриптора с добавленным `data: bytes`: `fileId`, `kind`, `fileName`, `mimeType`, `size`, `sha256`; у фотографии также `width`, `height`. Публичной ссылки или автоматического сохранения на диск нет.

Текущий SDK проверяет совпадение `fileId`, структуру дескриптора, размер, SHA-256 и сигнатуру типа файла. Это не антивирусная проверка и не проверка подлинности чека. Файл и base64-оболочка целиком обрабатываются в памяти, потоковой загрузки нет.

Если нужны чеки: принимайте PDF/фото в диалоге с ботом, связывайте их со своей заявкой и проверяйте бизнес-данные отдельно. Не считайте наличие PDF доказательством платежа и не выводите документ или его содержимое в журналы.

# 8. Отправка файлов и ограничения

### Отправка подготовленного файла

Пример обработчика `/receipt`: используйте только свой локальный файл. Этот фрагмент размещается внутри `make_router`, перед общим `on_text()`.

```python
from pathlib import Path

@router.on_command("/receipt")
async def receipt(update):
    await bot.send_document(
        update["chat"], Path("receipt.pdf"),
        request_id="receipt:" + update["updateId"],
        caption="Документ по вашей заявке",
    )
```

### Сигнатуры

```text
await bot.send_photo(
    chat, photo, *, request_id,
    file_name=None, caption="", timeout=60,
)
await bot.send_document(
    chat, document, *, request_id,
    file_name=None, caption="", timeout=60,
)
```

В `photo` / `document` передаются `bytes`, `bytearray`, `memoryview`, локальный `str`-путь или `pathlib.Path`. URL, открытый файловый объект и Telegram `file_id` вместо содержимого не поддерживаются.

Для байтов обязательно укажите `file_name`. Для пути по умолчанию используется имя файла без каталогов. Изображение не сжимается автоматически; заранее подготовьте подходящий JPEG/PNG.

| Параметр | Ограничение |
| --- | --- |
| Файл | От 1 байта до 10 MiB (10 485 760 байт). |
| Фото | JPEG или PNG; дескриптор до 64 000 000 пикселей. Локальная сигнатура не заменяет декодирование изображения сервером. |
| Документ | Только PDF с началом `%PDF-` и маркером `%%EOF` в последних 2048 байтах. |
| Имя | 1-128 символов, максимум 255 байт UTF-8; без `/`, `\`, управляющих символов и пробелов по краям. |
| Подпись | До 1024 байт UTF-8, не 1024 символов; допускаются переносы и табуляция. |
| Транспорт | JSON + base64, ограничение media-оболочки 14 MiB. |

Возвращается словарь: `version`, `messageId`, `botId`, `chat`, `text` (подпись), `attachment` (метаданные файла). SDK сверяет возвращённые параметры с отправкой. Автоматических повторов отправки нет; сохраняйте одинаковый `request_id` и неизменные данные при повторе неопределённого результата.

# 9. Подтверждения, повторы и порядок

### Рекомендуемая конфигурация

```python
dispatcher = Dispatcher(
    bot, router=router,
    limit=100, timeout=0,
    acknowledge=True,
    retry_transport=True,
    include_attachments=False,
)
await dispatcher.run_polling()
```

`poll_once()` выполняет один цикл и возвращает число обработанных обновлений. `run_polling()` повторяет циклы, ожидая 2 секунды после пустого ответа. `stop()` останавливает цикл и прерывает его ожидание.

Dispatcher валидирует весь полученный пакет, требует возрастающих ID и исполняет обработчики последовательно. Для одного бота используйте один активный consumer. Несколько независимых процессов не являются готовой схемой распределения нагрузки.

### Что означает acknowledge=True

После успешного выполнения обработчиков подтверждается завершённый префикс пакета. Если последующий обработчик падает, готовый префикс может быть подтверждён перед следующим опросом. При потере ответа подтверждение повторяется с прежним курсором; обработчики внутри того же живого экземпляра не запускаются заново только из-за потерянного ack.

Курсор и ожидающий ack хранятся в памяти процесса. После аварийного завершения необработанное подтверждение может привести к повторной доставке. Это не гарантия exactly-once для ваших побочных действий.

Без `acknowledge=True` Dispatcher двигает лишь локальный `offset`. Серверное подтверждение не выполняется. Прямой `get_updates` также не меняет ack.

### Идемпотентность вашего кода

Для ответов используйте стабильный ID, например `reply:` + `updateId`; для нескольких ответов добавляйте разные постоянные суффиксы. Не создавайте новый случайный ID после тайм-аута той же операции.

Отмена asyncio-задачи, `stop()` или сетевой тайм-аут не доказывают, что уже отправленная операция не была сохранена сервером. При неопределённом результате повторяйте ту же логическую отправку или callback-ответ с прежним `request_id` и неизменными параметрами. Отмена не является rollback; внешние побочные действия также требуют собственной устойчивой дедупликации. Для создания/смены токена сначала проверьте состояние BotFather, вместо слепого повтора.

Для записи заказа, начисления или другого внешнего действия храните собственный устойчивый ключ `(update["botId"], updateId, тип_операции)` в базе и делайте изменение транзакционно. Подтверждайте обновление после успешного завершения нужного действия.

### Границы автоматических повторов

`retry_transport=True` относится только к первоначальному discovery, чтению обновлений и отправке ack с `CloudBotTransportError.retryable=True`. Задержки: 2, 4, 8, 16 и 30 секунд - до пяти повторов после первой попытки.

Отправки, callback-ответы и исключения обработчиков автоматически не повторяются. Ошибка обработчика выходит из polling; настройте наблюдение за процессом и повторный запуск с собственной защитой от дублей. Неподходящий токен, невалидные данные и постоянные ошибки нельзя исправить бесконечным циклом повторов.

# 10. Method objects и тестовый транспорт

Классы методов - дополнительный способ вызвать те же операции. Они экспортируются из `aiovl`; используйте `.execute(bot)`. Конструкция `await bot(method)` текущим клиентом не реализована.

```python
from aiovl import SendMessage, GetUpdates

result = await SendMessage(
    chat=update["chat"], text="Здравствуйте",
    request_id="reply:" + update["updateId"],
).execute(bot)

updates = await GetUpdates(
    limit=20, timeout=0,
).execute(bot)
```

| Класс | Поля нового вызова через именованные аргументы |
| --- | --- |
| `SendMessage` | `chat, text, request_id, reply_markup=None` |
| `SendPhoto` | `chat, photo, request_id, file_name=None, caption=""` |
| `SendDocument` | `chat, document, request_id, file_name=None, caption=""` |
| `GetAttachment` | `chat, file_id` |
| `GetMe` | `timeout=30` |
| `GetUpdates` | `offset=None, limit=100, timeout=0, request_timeout=60, include_attachments=False` |
| `AcknowledgeUpdates` | `through` |
| `AnswerCallbackQuery` | `callback_query_id, request_id, text="", show_alert=False` |

Все прежние позиции конструктора с `bot_id` сохранены. Для нового кода пропускайте `bot_id` и используйте именованные аргументы; например `SendMessage(chat=chat, text="Привет", request_id="reply:1")`. Отсутствие обязательных данных всё равно отклоняется в конструкторе или при `.execute(bot)`.

Объекты методов не добавляют очередей, повторов или новых серверных возможностей. Для настройки тайм-аута отправки вызывайте методы `Bot` напрямую.

### Локальное тестирование без сети и настоящего токена

```python
import asyncio
import secrets
from aiovl import Bot

async def transport(method, path, headers, body, timeout):
    assert method == "POST"
    # Не печатайте headers/body: в них могут быть секреты и данные.
    if path == "/v1/cloud-bots/getMe":
        return {"ok": True, "result": {"version": 1, "botId": "bot_example_01"}}
    assert path == "/v1/cloud-bots/getUpdates"
    return {"ok": True, "result": []}

async def test():
    bot = Bot(secrets.token_hex(24), transport=transport,
              base_url="https://example.invalid")
    assert await bot.get_updates() == []

asyncio.run(test())
```

Адаптер получает HTTP-метод, относительный путь, заголовки, JSON в `bytes` и тайм-аут. Он должен вернуть словарь оболочки `{"ok": True, "result": ...}`, а не готовый `result`. Для реального транспорта сохраняйте TLS, авторизацию и ограничения размеров.

# 11. Перенос Telegram / aiogram 3 → aiovl

Это перенос поддерживаемой бизнес-логики, а не смена одного import. Ни Telegram token, ни Telegram `chat_id`, `file_id`, callback ID или сохранённый Telegram offset не подходят для VLook. Создайте отдельного бота в VLook, выдайте ему собственный bot token и храните состояния двух систем раздельно.

### Точная карта основных вызовов

| Telegram / aiogram 3 | aiovl | Что изменить |
| --- | --- | --- |
| `Bot(token=telegram_token)` | `Bot(vlook_token)` | Токен из VLook BotFather; основной HTTPS origin уже задан. |
| `await bot.get_me()` | `await bot.get_me()` | Результат aiovl — словарь `version, botId`, не Telegram User. |
| `@router.message(Command("start"))` | `@router.on_command("/start")` | Передаётся словарь update; slash обязателен, совпадение первого слова точное. |
| `@router.message(F.text)` | `@router.on_text()` | `message.text` → `update["text"]`; общий обработчик после команд. |
| `@router.callback_query(F.data == "ok")` | `@router.on_callback("ok")` | `query.data/id` → `update["callbackQuery"]["data"/"id"]`. |
| `await message.answer(text)` / `bot.send_message(chat_id, text)` | `await bot.send_message(update["chat"], text, request_id=stable_id)` | Нет `Message.answer`/DI; добавьте устойчивый ID операции. |
| `await query.answer(text=...)` | `await bot.answer_callback_query(query_id, request_id=stable_id, text=...)` | Ответ callback обязателен перед ack; отправка текста в чат его не заменяет. |
| `Dispatcher(); include_router(router); start_polling(bot)` | `Dispatcher(bot, router=router, acknowledge=True, retry_transport=True).run_polling()` | Один последовательный private-chat consumer; `timeout=0`. |
| `@router.message(F.photo)` / `F.document` | `@router.on_photo()` / `on_document()` | `include_attachments=True`; один descriptor, не массив Telegram PhotoSize. |
| `send_photo(..., FSInputFile(path))` | `send_photo(chat, Path(path), request_id=stable_id)` | Только JPEG/PNG; `Path`/bytes вместо Telegram InputFile. |
| `send_document(..., FSInputFile(path))` | `send_document(chat, Path(path), request_id=stable_id)` | Только PDF; до 10 MiB. |
| `get_file` + `download_file` | `get_attachment(chat, update["attachment"]["fileId"])` | Возвращает проверенные bytes; публичного download URL нет. |

Синтаксис Telegram/aiogram сверён 12.10.2026 с официальными [Router](https://docs.aiogram.dev/en/latest/dispatcher/router.html), [Command](https://docs.aiogram.dev/en/latest/dispatcher/filters/command.html), [Dispatcher](https://docs.aiogram.dev/en/latest/dispatcher/dispatcher.html) и [answerCallbackQuery](https://docs.aiogram.dev/en/latest/api/methods/answer_callback_query.html). Колонка aiovl описывает именно текущие исходники и автономные SDK-тесты.

### Приватный чат, команды и состояние

VLook update содержит `chat={"kind":"private","id":"chat_…"}`. Используйте этот объект при ответе. Telegram `message.chat.id` и `message.from_user.id` не переводятся в VLook ID; не перенесите Telegram список клиентов как адреса получателей. Если ваш сервис требует связать аккаунты, нужна отдельная явно согласованная бизнес-процедура; SDK не выдаёт данные Telegram-пользователя.

Аргументы команды извлекайте сами, например `parts = update["text"].split(maxsplit=1)`. `/start@name`, фильтры aiogram, deep links, FSM, middleware, dependency injection, автоматическое HTML/Markdown форматирование и Telegram entities здесь не реализованы. Состояние заявки/диалога храните в своей базе с ключом VLook chat; исключите токены, содержимое чужих чатов и файлы из журналов.

### Клавиатуры и callback

Перепишите `InlineKeyboardMarkup(inline_keyboard=...)` в `{"type":"inline","rows":[[{"text":"OK","callbackData":"ok"}]]}`. Поле Telegram `callback_data` становится `callbackData`. `ReplyKeyboardMarkup(keyboard=...)` превращается в `{"type":"reply","rows":[[{"text":"Помощь"}]]}`, `ReplyKeyboardRemove()` — в `{"type":"remove"}`. URL, login, web app, pay, switch-inline и request-contact/location кнопки не поддерживаются.

Поставьте точные callback-обработчики перед общим `@router.on_callback()`. Общий обработчик должен отвечать на устаревшие/неизвестные данные. Используйте `request_id="answer:" + query["id"]`; после успешного callback-ответа отдельное сообщение отправляется через `send_message` с другим стабильным ID. Действуют лимиты разметки из раздела 4 и ограниченный сервером срок callback; не выполняйте длительную работу до ответа.

### Polling и подтверждения отличаются

В Telegram вызов `getUpdates` с offset выше update ID подтверждает старые обновления. В VLook `offset` лишь выбирает ID строго больше значения; для удаления обработанного префикса нужен отдельный `acknowledge_updates`. Не копируйте Telegram схему `offset = update_id + 1`: ID VLook — десятичные строки, а нижняя граница исключительная. Это различие сверено с [официальным Telegram getUpdates](https://core.telegram.org/bots/api#getupdates).

Для типичного переноса включите `acknowledge=True`. После внешнего побочного действия, но до ack возможна повторная доставка. Ваши заявки/платёжные состояния должны использовать транзакционную дедупликацию `(update["botId"], update["updateId"], operation)`. Для ответов используйте стабильный `request_id`, например `reply:<updateId>:status`; после тайм-аута не создавайте новый ID. Отправки и ошибки обработчиков не повторяются автоматически. Для смены или отзыва токена остановите старый процесс и перенастройте секрет, не меняйте токен автоматически после любого сетевого сбоя.

### Фото/PDF и неподдерживаемые функции

Для фото и PDF перенесите только подходящую часть кода: байты или локальный путь, JPEG/PNG/PDF, до 10 MiB, подпись до 1024 UTF-8 байт, фото до 64 миллионов пикселей в descriptor. Сценарий SDK ↔ основной HTTPS API проверен 12.10.2026; нужен поддерживающий media клиент, а в native53/54 пользовательский bot-media UI ещё не реализован. Telegram `file_id`, URL, multipart/streaming, произвольные документы, видео, voice, audio и media groups отсутствуют. Полученный файл в bytes не считается безопасным исполняемым содержимым или подтверждённым чеком.

Группы/каналы, edit/delete/forward Telegram-сообщений, администрирование участников, inline queries, webhook, payment/provider API и web apps через этот SDK не предоставляются. Выделите такие функции в исходном боте до переноса и сообщите пользователю о недоступности, а не заменяйте их фиктивным успехом. Облачный чат VLook-бота доступен сервису и коду бота; он не получает E2EE ключи обычных Matrix-переписок.

### Задание для агента, переносящего существующего бота

Сначала составьте список обработчиков и внешних эффектов, отметьте поддерживаемые private text/commands/callback/JPEG/PNG/PDF и зависимости от неподдерживаемых Telegram функций. Затем замените транспорт и формы обновлений по таблице, сохранив бизнес-функции отдельно. Используйте новый VLook token, `Bot(token)`, `Dispatcher(bot, router=router)` и устойчивые request ID. Добавьте локальные тесты команды, неизвестного callback, повторной доставки, потерянного ack, отзыва токена и границ файлов. Не запускайте реальные рассылки или платежи ради проверки. После локальных тестов отдельно подтвердите доступность нужных endpoint и сценарий в актуальном VLook-клиенте; перенос не считается проверенным только потому, что imports проходят.

# 12. Диагностика и границы поддержки

### Ошибки SDK

| Исключение / симптом | Что проверить |
| --- | --- |
| `CloudBotValidationError` | Форму `chat`, необязательный явный `bot_id`, обязательный `request_id`, длины текста, MIME и размер файла. Некоторые проверки касаются также входящих обновлений. |
| `CloudBotTransportError` | Сеть, сертификат, origin, токен, доступ сервиса и корректность ответа. Поле `retryable` означает возможность ограниченного повтора, а не гарантию успеха. |
| `CloudBotError` | Общий базовый класс двух ошибок выше. |
| Бот молчит | Процесс должен работать; пользователь должен отправить сообщение; проверьте порядок обработчиков и поддержку формы update. |
| Callback останавливает polling | Каждый полученный callback должен быть успешно отвечен. Добавьте общий обработчик неизвестных callback. |
| Вложения не приходят | Нужны `include_attachments=True`, обработчики файлов и поддерживающие media версии сервера и клиента VLook. |
| После перезапуска дубли | Используйте серверный ack и устойчивую идемпотентность своих действий. |

HTTP-код и тело ответа намеренно не включаются в обычный текст ошибки. Не ожидайте атрибута `.status_code`: SDK его не предоставляет. Для диагностики записывайте тип ошибки, этап и безопасный результат операции, без заголовков авторизации, содержимого сообщений и файлов.

### Чего текущий SDK не предоставляет

- Полную совместимость с Telegram Bot API / aiogram, FSM, middleware и готовые модели Telegram.
- Групповых ботов, звонки, голосовые сообщения, видео, альбомы и произвольные форматы документов.
- Готовый API настройки webhook, web app, платежей или запуска кода внутри VLook.
- Методы создания бота и управления токеном из Python: это действия владельца в VLook.
- E2EE переписку пользователя с облачным ботом, автоматическую очистку памяти Python или антивирусную проверку файлов.
- Гарантию фоновой работы без запущенного процесса или доставки при недоступном сервере.

При polling не нужен публичный входящий HTTP-порт вашего компьютера. Нужен исходящий HTTPS-доступ к основному серверу. Документ описывает локальный SDK 0.0.1.dev1; наличие метода в исходниках не означает завершённую публикацию каждой возможности.

### Источники и сопровождение

Руководство сверено с модулями `aiovl/client.py`, `dispatcher.py`, `methods.py`, `__init__.py`, `pyproject.toml` и автономными тестами `tests/test_aiovl*.py`. SDK распространяется по MIT; сведения об адаптированных элементах aiogram и лицензиях находятся в `LICENSE`, `NOTICE.md` и `aiovl/UPSTREAM.json`.

Примеры содержат только синтетические ID. При обновлении SDK сверяйте фактические сигнатуры и требования сервера; текущая версия является экспериментальной. Границы подтверждённой проверки SDK/HTTPS и незавершённого клиентского bot-media UI указаны на первой странице.
